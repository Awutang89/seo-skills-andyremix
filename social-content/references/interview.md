# Interview

Read this when the source is thin, no platform is named, or the person wants a reusable voice setup.

## Principle

Ask only what stands between the skill and a post worth publishing. A request for one LinkedIn post is not an invitation to run a brand strategy session. Every question goes through the structured question tool, bundled into one call where possible (see the Question rule in SKILL.md).

## When to ask

Ask two or three questions when the request has:

- only a broad topic
- no platform
- no reader in mind
- no proof, example or point of view
- a risky claim that needs checking
- an idea that sits outside the saved pillars

## When not to ask

- Quick mode, or the person said no questions.
- The source already carries proof, reader, platform and voice.
- The job is a light rewrite of a draft they supplied.

## The post questions

Pick only the gaps. Say it in plain words, for example:

> Before I write this, I need two or three things:
> 1. Where is it going: X, Meta Threads or LinkedIn?
> 2. What real proof, moment, result or example should it stand on?
> 3. Who should read it, and what should they think differently afterwards?

X with length in doubt: one routing question.

> Can you post long on X (Premium), or should I keep this under 280 characters?

Risky claim (health, legal, money, safety, guaranteed results): swap one question for an evidence question.

> What evidence can we point to for that claim? If it is thin, should I soften the wording?

## Voice setup

No profile exists and the person seems to want an ongoing workflow: offer a compact setup in one call. Ask for:

- the goal and the reader
- three to five content pillars
- platform priorities
- X status: standard or Premium
- banned words and moves
- two or three of their own posts, or posts they admire
- optional visual taste
- website URL, brand colors, logo and visual examples, if they want branded diagrams or stat cards
- where to save reusable social work (examples: `example-brand/social/`, `content/social/`, or a hidden `.social-content/`)

Never create a default folder. The answer to the last question becomes `SOCIAL_WORKSPACE`.

Then run the scheduler check in `scheduler-handoff.md`. If one is installed, ask whether approved posts should come with an offer to queue them as drafts. That is a delivery preference and never blocks a draft.

If the person wants speed, go ahead on a temporary voice assumption drawn from the brief, and label it as temporary.

## Quick mode

- No discovery questions.
- Still load any existing profile and examples.
- State a temporary assumption only when it changes the draft.
- Invent nothing.
- If proof is thin, write a narrower post led by opinion instead of a broad one padded with fake detail.

## After the answers

1. Pull out proof and constraints.
2. Draft for the requested platforms.
3. If setup captured website, colors, logo notes or visual taste, save them to the social profile.
4. If setup captured a scheduler preference, save that too.
5. Asking whether to save a profile or packet is itself a question: use the tool.

Saving happens once it is clearly useful. It never holds up the first draft.
